Four things change when the fleet gets big

Running one agent is a terminal problem. Running twelve is an attention problem, a continuity problem, and a context problem. Flight Deck is built around those.

Shipped working today Building in progress Planned designed, not yet built

Run a fleet, not a tab

One window holds every agent you have running, grouped the way you already think about work: session inside project. You stop being the router between a dozen terminal windows you can't tell apart.

  1. Every agent in one place

    Sessions nest under the project they belong to. Add a project by dropping a folder on the sidebar.

    Shipped

  2. Five agents, side by side

    Open a tab on Claude Code, Codex, Grok, Gemini or OpenCode. Each is a first-class row with live status, transcript search, and a model you pick per agent and per project.

    Shipped

  3. Real terminals, not log viewers

    Each session is a genuine PTY rendered by the Ghostty engine on Metal — full escape-sequence fidelity, real scrollback, real input. Your agent behaves exactly as it does in a terminal, because it is in one.

    Shipped

  4. Move at keyboard speed

    ⌘N opens a session, ⌘⇧[ and ⌘⇧] walk the whole fleet across project boundaries, ⌘W closes the session rather than the window, and ⌘⇧T brings back what you just closed. ⌃⌘← and ⌃⌘→ go back and forward through the tabs you've visited, like a browser. ⌘⇧/ lists every shortcut.

    Shipped

  5. Find any conversation, from any agent

    ⌘K searches session and project names plus the transcript history of every project in the sidebar, across all five agents, with the matching words in context. Jump to a live session, or resume an old conversation into a new tab on its own agent.

    Shipped

  6. Drive the fleet from a script

    A flightdeck command-line tool talks to the running app over a local control socket, from any tab's own shell: list sessions, send one a prompt, wait for the answer, or run a command on another machine. Agents can orchestrate agents.

    Shipped

  7. Arranged the way you think

    Reorder sessions within a project and drag projects themselves into the order you want. Collapse the ones you're not watching.

    Shipped

  8. Isolation when you want it

    Opt a session into its own git worktree and branch, review its diffs in place, then merge or discard — so parallel agents only collide where you let them.

    Planned

Know who needs you, without looking

The expensive part of running many agents isn't starting them — it's noticing when one stops. Every row reports what its agent is doing, continuously, so your attention goes where it's actually needed.

  1. Four states, told by shape and colour

    Working, blocked on you, running a background command, or idle. Distinct glyph and distinct tint for each — never colour alone — with the same distinction in the tooltip and for VoiceOver.

    Shipped

  2. Subagent fan-out, live

    When a session dispatches parallel subagents, the count appears next to its spinner, and the tooltip names the one waiting on you. You can see which sessions are genuinely expensive right now.

    Shipped

  3. Nothing finishes into the void

    A session that completes while you're in another tab keeps an unread mark until you actually look at it — and the mark survives a relaunch.

    Shipped

  4. Folded projects still tell the truth

    A collapsed project shows its session count and the most demanding state underneath it. A blocked agent can't hide inside a group you closed.

    Shipped

  5. Notified only when it matters

    System notifications on the transitions worth interrupting for — a permission prompt, a finished run — not on every token.

    Shipped

  6. Usage you can see coming

    Each account's rate-limit windows show as meters with soft and hard limits, fed by every tab and planning run that bills it.

    Shipped

  7. The fleet in your pocket

    An iPhone companion pairs with your Mac over the local network — scan a QR code or type a short code — and shows the same fleet: every project, every session, with the conversation readable. It opens instantly on the fleet it last saw. Rename, mark read, or close from either side.

    Shipped

  8. Answer a blocked agent from the phone

    When an agent stops to ask you something, the question or permission prompt appears on your phone, for every supported agent. Pick an option, type an answer, or dismiss it, and the agent carries on. A half-written reply survives a crash.

    Shipped

  9. Subagents, menus and sign-ins too

    See a session's subagents on the phone and answer the one that is actually asking. Numbered menus and sign-in prompts that only appear on an agent's screen reach the phone as well, so a login never strands an agent.

    Shipped

  10. Context budget per session

    How much of its window each session has burned, inline on the row, so you can see which conversation is about to compact before it does.

    Planned

Close the lid without losing the fleet

A dozen live conversations is a lot of state to lose to a restart. Flight Deck treats the whole fleet as durable: quit, update, reboot, and come back to the same deck you left — and borrow another machine when this one isn't enough.

  1. Sessions survive a relaunch

    Every session returns, each reattached to its own conversation rather than starting a fresh one — along with its project grouping, order, and collapsed state.

    Shipped

  2. Agents keep running when the app doesn't

    Each session lives in a small background daemon, so quitting or crashing Flight Deck doesn't take the agent down with it. Reopen the app and reattach to a terminal that kept going.

    Shipped

  3. Idle sessions go to sleep

    A session that's been quiet for a while is paused and its terminal released, so a big fleet doesn't cost you battery. Select it and it wakes with nothing lost. Threshold is a preference, with an Off switch.

    Shipped

  4. Retry through API hiccups

    A transient API failure can retry on a backing-off ladder, with a countdown banner on the session, instead of leaving an agent stalled overnight. Off by default; turn it on in preferences.

    Shipped

  5. Names stay honest

    A session's title tracks what its agent is actually working on, in both directions — rename from the sidebar and the agent follows, or let the conversation name the row.

    Shipped

  6. Work in flight gets picked back up

    Sessions that were mid-task at shutdown are offered a nudge to continue once they settle, so a restart costs you a keystroke instead of the thread. Per-session toggle if you'd rather it didn't.

    Shipped

  7. Two tabs on one conversation, caught

    If two sessions end up pointed at the same conversation, both rows say so instead of silently interleaving their turns.

    Shipped

  8. Pair another Mac or Linux box

    Settings → Hosts pairs a second Mac with a short code, or a Linux machine with one pasted command, over the LAN or Tailscale.

    Shipped

  9. Run it on another machine

    flightdeck run --on <host> syncs your uncommitted work, streams the output and returns the remote exit code. Bring the changes back with diff and apply, and keep services up with their ports forwarded. Recipes and routes let agents send UI tests or heavy builds elsewhere on their own.

    Shipped

  10. Cloud machines on demand

    Declare a machine and Flight Deck creates it in your own AWS or GCP account when a run needs it, with a cost line on every command and a hard time, idle and budget limit that destroys it.

    Building

Own the context instead of guessing at it

This is the part that isn't a terminal feature. Your harness owns its private context window — but Flight Deck runs a parallel layer beside it that you can read, edit, and audit. What went in, where it came from, and why.

  1. Per-project agent configuration

    Set each agent's flags and model globally, then override them per project, from real controls instead of a remembered command line. Flags the app doesn't recognise are preserved verbatim rather than dropped.

    Shipped

  2. Accounts and pools

    Add several logins per agent, group them into pools, and assign an account or pool per agent, per project or per folder. New tabs lease from the pool with the most headroom, and /switch-account moves a live conversation to another login.

    Shipped

  3. Five agents, one adapter

    Claude Code, Codex, Grok, Gemini and OpenCode all normalise into a single event stream, so the sidebar, the notifications, search, and the phone work the same regardless of what's driving the session.

    Shipped

  4. Flight Control: plan with a fleet

    Turn a rough idea into a plan that agents from up to five families have worked over in rounds, with a second family cross-checking the first. Edit and annotate the plan in place, watch a live board of who's doing what, and see how much of it is covered and when it has settled. Steer, choose fidelity and edit rounds from your phone.

    Shipped

  5. Tasks routed to the right model

    Write routing rules in plain words. Flight Control compiles them, ranks models from a cited benchmark index, and sends each released task to the model that suits its kind.

    Shipped

  6. Swarms that work the task list

    Launch a swarm on a project's released tasks. It fills slots, hands an agent to a fresh account when one runs low, and pauses or resumes from your phone.

    Building

  7. Task-scoped context, assembled per turn

    Relevant index results, memory, and terminal output gathered for the prompt you just typed and injected as it goes — with a provenance view showing exactly what was added.

    Planned

  8. One code index, shared by every session

    An incremental index of symbols, references, and call graphs — built once, served to every agent over MCP, instead of each session re-reading the same files to discover the same structure.

    Planned

  9. Memory you approve, not memory you discover

    Decisions and facts are mined from the event stream and proposed to you; what you accept persists and rolls up from session to project.

    Planned

  10. Compaction you can open

    When Flight Deck's own layer summarises, the summary is a document you can read and edit — not a thing that quietly happened to your conversation.

    Planned
Under the hood

Authentically Apple

Mac-native, from chrome to core

Swift + AppKit + SwiftUI on Metal. It behaves the way the rest of your Mac behaves — sidebar materials, real menus, keyboard conventions, VoiceOver.

A real terminal, reused

The terminal isn't a reimplementation. Flight Deck embeds Ghostty's engine and surface — the same renderer, input encoding, and escape handling — pinned to a known-good release.

Your state, on your disk

Sessions live in a plain JSON file in Application Support and preferences in the standard defaults domain. Nothing about your fleet is stored anywhere but your machines.
