What you get

Four things change when the fleet gets big

Running one agent is a terminal problem. Running twelve is an attention problem, a continuity problem, and a context problem. Flight Deck is built around those.

Shipped working today Building in progress Planned designed, not yet built

Run a fleet, not a tab

One window holds every agent you have running, grouped the way you already think about work: session inside project. You stop being the router between a dozen terminal windows you can't tell apart.

  1. Every agent in one place

    Sessions nest under the project they belong to. Add a project by dropping a folder on the sidebar.

    Shipped

  2. Real terminals, not log viewers

    Each session is a genuine PTY rendered by the Ghostty engine on Metal — full escape-sequence fidelity, real scrollback, real input. Your agent behaves exactly as it does in a terminal, because it is in one.

    Shipped

  3. Move at keyboard speed

    ⌘N opens a session, ⌘⇧[ and ⌘⇧] walk the whole fleet across project boundaries, ⌘W closes the session rather than the window.

    Shipped

  4. Arranged the way you think

    Drag sessions between projects and reorder projects themselves with the same gesture. Collapse the ones you're not watching.

    Shipped

  5. Isolation when you want it

    Opt a session into its own git worktree and branch, review its diffs in place, then merge or discard — so parallel agents only collide where you let them.

    Planned

Know who needs you, without looking

The expensive part of running many agents isn't starting them — it's noticing when one stops. Every row reports what its agent is doing, continuously, so your attention goes where it's actually needed.

  1. Four states, told by shape and colour

    Working, blocked on you, running a background command, or idle. Distinct glyph and distinct tint for each — never colour alone — with the same distinction in the tooltip and for VoiceOver.

    Shipped

  2. Subagent fan-out, live

    When a session dispatches parallel subagents, the count appears next to its spinner. You can see which sessions are genuinely expensive right now.

    Shipped

  3. Nothing finishes into the void

    A session that completes while you're in another tab keeps an unread mark until you actually look at it — and the mark survives a relaunch.

    Shipped

  4. Folded projects still tell the truth

    A collapsed project shows its session count and the most demanding state underneath it. A blocked agent can't hide inside a group you closed.

    Shipped

  5. Notified only when it matters

    System notifications on the transitions worth interrupting for — a permission prompt, a finished run — not on every token.

    Shipped

  6. Context budget per session

    How much of its window each session has burned, inline on the row, so you can see which conversation is about to compact before it does.

    Planned

Close the lid without losing the fleet

A dozen live conversations is a lot of state to lose to a restart. Flight Deck treats the whole fleet as durable: quit, update, reboot, and come back to the same deck you left.

  1. Sessions survive a relaunch

    Every session returns, each reattached to its own conversation rather than starting a fresh one — along with its project grouping, order, and collapsed state.

    Shipped

  2. Names stay honest

    A session's title tracks what its agent is actually working on, in both directions — rename from the sidebar and the agent follows, or let the conversation name the row.

    Shipped

  3. Work in flight gets picked back up

    Sessions that were mid-task at shutdown are offered a nudge to continue once they settle, so a restart costs you a keystroke instead of the thread. Per-session toggle if you'd rather it didn't.

    Shipped

  4. Two tabs on one conversation, caught

    If two sessions end up pointed at the same conversation, both rows say so instead of silently interleaving their turns.

    Shipped

Own the context instead of guessing at it

This is the part that isn't a terminal feature. Your harness owns its private context window — but Flight Deck runs a parallel layer beside it that you can read, edit, and audit. What went in, where it came from, and why.

  1. Per-project agent configuration

    Set your agent's flags globally, then override them per project, from real controls instead of a remembered command line. Flags the app doesn't recognise are preserved verbatim rather than dropped.

    Shipped

  2. One code index, shared by every session

    An incremental index of symbols, references, and call graphs — built once, served to every agent over MCP, instead of each session re-reading the same files to discover the same structure.

    Building

  3. Any harness behind one adapter

    Claude Code and opencode normalise into a single event stream, so the sidebar, the notifications, and the context layer work the same regardless of what's driving the session.

    Building

  4. Task-scoped context, assembled per turn

    Relevant index results, memory, and terminal output gathered for the prompt you just typed and injected as it goes — with a provenance view showing exactly what was added.

    Planned

  5. Memory you approve, not memory you discover

    Decisions and facts are mined from the event stream and proposed to you; what you accept persists and rolls up from session to project.

    Planned

  6. Compaction you can open

    When Flight Deck's own layer summarises, the summary is a document you can read and edit — not a thing that quietly happened to your conversation.

    Planned
Under the hood

Authentically Apple

Mac-native, from chrome to core

Swift + AppKit + SwiftUI on Metal. It behaves the way the rest of your Mac behaves — sidebar materials, real menus, keyboard conventions, VoiceOver.

A real terminal, reused

The terminal isn't a reimplementation. Flight Deck embeds Ghostty's engine and surface — the same renderer, input encoding, and escape handling — pinned to a known-good release.

Your state, on your disk

Sessions live in a plain JSON file in Application Support and preferences in the standard defaults domain. Nothing about your fleet is stored anywhere but your machine.
