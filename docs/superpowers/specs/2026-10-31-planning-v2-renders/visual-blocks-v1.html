This plan has UI and a multi-component flow. Should I make visuals as I plan? (choose any)
  1. States and sizes come from the comp's manifest. A provider declares which states and sizes it supports, and the segmented controls are built from that list.
  2. Pins (yellow, numbered) are notes anchored to an element. Each one stores a CSS selector, the element's text, and an x/y fallback, so it survives small revisions. A ✦ blue pin is an Ask thread anchored to that element. Pins are notes, so they go to rounds like any other note.
  3. An amber-outlined thumbnail is an alternate a round proposed, with that round's reason. Only you can make it ★ primary.
  4. Edit mode allows text edits only: you click into text and change it. Saving creates a new revision, r<n>, and the edit is fed to later threads and rounds as a human edit, so no one regenerates over it.
  5. The cost estimate comes from the provider's manifest and is scaled by the chosen model's price. It's labelled ≈ because it is an estimate.
